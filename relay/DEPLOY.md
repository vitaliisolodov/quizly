# Онлайн-гра через Socket.IO

Папка `relay` містить сервер для онлайн-кімнат. GitHub Pages продовжує віддавати інтерфейс. Socket.IO використовує HTTPS long-polling і переходить на WebSocket, якщо мережа його підтримує. Створення кімнати, QR і PIN працюють у тому самому інтерфейсі.

1. Створіть один Node.js Web Service на хостингу з HTTPS і підтримкою Socket.IO, наприклад Render.
2. Підключіть цей репозиторій. У полі Root Directory вкажіть `relay`, Build Command — `npm ci`, Start Command — `npm start`, Health Check Path — `/health`.
3. Задайте `QUIZLY_ORIGINS` як origin вашого GitHub Pages без назви репозиторію і без кінцевого `/`. Для поточного сайту це `https://vitaliisolodov.github.io`.
4. Відкрийте `/health` на адресі сервісу і перевірте, що він повертає `ok`.
5. Вкажіть HTTPS-адресу сервісу в `deployedRelay` у `transport-config.js` і опублікуйте зміни на GitHub Pages. Поки адреса порожня, опублікований сайт використовує PeerJS.
6. Відкрийте оновлений сайт на обох пристроях і створіть нову кімнату.

Для перевірки на одному комп’ютері запустіть `npm ci` і `npm start` у папці `relay`. У другому терміналі з кореня GitHub Pages-версії виконайте `npx serve . -l 8080` і відкрийте `http://localhost:8080` у двох вкладках. Перевірка з телефона потребує опублікованого HTTPS-сайту та доступного HTTPS-сервера.

Сервер передає зашифровану анкету браузеру ведучого. QR містить відбиток публічного ключа, за яким телефон перевіряє, що шифрує дані для потрібного ведучого. При ручному введенні PIN телефон довіряє ключу, отриманому від налаштованого сервера. Ключ розшифрування та CSV залишаються в браузері ведучого.

Пробна версія розрахована на один екземпляр сервера. Вкладка ведучого зберігає стан гри та має залишатися відкритою. Після зміни версії на хостингу починайте нову гру. Перед подією перевірте підключення на проблемних телефонах і на мережі майданчика.
